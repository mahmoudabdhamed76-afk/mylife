# My Life — متابعة صحتك اليومية

تطبيق ويب عربي (RTL) لمتابعة **سكر الدم**، **السكر التراكمي HbA1c**، **رحلة الوزن**، **الأكل والسعرات**، **ضغط الدم**، **المياه**، **الرياضة**، و**الأدوية** — **بتزامن بين كل أجهزتك** بحساب واحد.

---

## المميزات

| القسم | التفاصيل |
|---|---|
| التزامن | حساب باسم مستخدم وكلمة سر، والبيانات بتتزامن تلقائياً كل ١٥ ثانية ومع كل تعديل. الأحدث يفوز لو عدّلت من جهازين. بيشتغل أوفلاين والتغييرات بتترفع أول ما النت يرجع |
| الكروت المتداخلة | ديك كروت في الرئيسية بتتسحب باللمس بحركة spring — كل كارت بلونه (السكر، المونجارو، الوزن، التراكمي، التحاليل، الضغط) والباقي بيطلّ من ورا |
| المونجارو | تسجيل كل جرعة (المقدار، المكان، الوقت)، وعدّاد تنازلي للجرعة الجاية على الشاشة الرئيسية، وتنبيه لو الموعد فات |
| التحاليل | كوليسترول كلي و LDL و HDL والدهون الثلاثية ووظائف الكبد والكلى وفيتامين د والهيموجلوبين — مع النطاقات المرجعية واتجاه كل تحليل عن السابق |
| المساعد | شاشة بتلخّص الوزن والمونجارو والتحاليل والسكر في مكان واحد، مع تنبيهات مرتّبة حسب الأهمية |
| سكر الدم | قراءات بتوقيتها (صايم / قبل الأكل / بعد الأكل / عشوائي / قبل النوم / أثناء الليل)، شريط تدريج بيوضّح مكان القراءة من النطاق المستهدف، وتنبيه للقراءات الخطرة |
| السكر التراكمي | تسجيل HbA1c + تحويله لمتوسط سكر تقديري، وحساب تراكمي تقديري من القراءات اليومية |
| رحلة الوزن | قياس يومي، نسبة التقدم للهدف، المعدل الأسبوعي بانحدار خطي على ٢١ يوم، التاريخ المتوقع للوصول، سلسلة القياس، تقويم انتظام ٣٠ يوم |
| الأكل | ~٩٠ أكلة مصرية بالسعرات والكارب + إدخال يدوي، على ٤ وجبات |
| الأدوية | مواعيد الجرعات، تتبع الالتزام، وإشعارات تذكير |
| التقارير | الوقت في النطاق، المتوسط حسب كل توقيت، رسوم SVG، وتقرير مطبوع للدكتور |
| المظهر | نهاري / ليلي / تلقائي + حركة spring كاملة، وألوان مميزة لكل قسم |
| الخصوصية | قفل بكود ٤ أرقام (محلي لكل جهاز)، تصدير JSON و CSV |

## المتطلبات

Node.js **22 أو أحدث** — صفر dependencies (`node:http` + `node:sqlite` + `node:crypto`).

## التشغيل محلياً

```bash
npm start          # http://localhost:3000
npm run dev        # مع إعادة تشغيل تلقائي
```

قاعدة البيانات تتعمل في `./data/mylife.db` تلقائياً.

---

## النشر على Railway

1. ارفع الريبو على GitHub، وفي Railway: **New Project → Deploy from GitHub repo**.
2. **ركّب Volume** (مهم جداً — من غيره الحسابات تتمسح مع كل deploy):
   - Service → **Settings → Volumes → New Volume**
   - Mount path: `/data`
3. مش محتاج تظبط أي متغير — السيرفر بيقرا `RAILWAY_VOLUME_MOUNT_PATH` تلقائياً.
4. **Settings → Networking → Generate Domain**.

> ⚠️ ماتزوّدش عدد الـreplicas. SQLite لازم كاتب واحد بس.

### متغيرات اختيارية

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `PORT` | 3000 | بورت الاستماع (Railway بيظبطه لوحده) |
| `DATA_DIR` | volume أو `./data` | مسار قاعدة البيانات |
| `REGISTER_CODE` | فاضي | لو ظبطته، مفيش حساب جديد يتعمل غير بالكود. **سيبه فاضي = أي حد يعرف اللينك يقدر يعمل حساب** |

### حسابات متعددة

السيرفر بيدعم عدد غير محدود من الحسابات، وكل حساب معزول تماماً عن التاني (مُختبر). كل واحد بيسجّل دخول باسمه على أجهزته وبياناته بتتزامن لوحدها.

> اظبط `REGISTER_CODE` من أول يوم لو الرابط عام. من غيره أي حد يلاقي اللينك يقدر يفتح حساب على السيرفر بتاعك.

### أو بـ Docker

```bash
docker build -t my-life .
docker run -p 3000:3000 -v mylife-data:/data -e DATA_DIR=/data my-life
```

## الـAPI

| المسار | الوظيفة |
|---|---|
| `POST /api/register` | حساب جديد `{uname, pass}` → `{token}` |
| `POST /api/login` | دخول → `{token}` |
| `POST /api/sync` | `{since, recs[], prof}` → `{now, recs[], prof}` |
| `POST /api/logout` | إنهاء الجلسة |
| `GET /healthz` | فحص الصحة |

المصادقة بـ `Authorization: Bearer <token>`.

## الأمان

- كلمات السر بـ `scrypt` مع salt عشوائي لكل مستخدم ومقارنة timing-safe
- جلسات ٩٠ يوم بتوكن ٢٥٦-بت
- حد للمحاولات على الدخول والتسجيل، وسقف لحجم الطلب
- كل مستخدم معزول تماماً عن التاني (مُختبر)
- الـPIN والإشعارات محلية لكل جهاز ومابتتزامنش

> السجلات نفسها متخزّنة JSON عادي في SQLite. لو محتاج تشفير at-rest أو end-to-end، ده تعديل لازم يتعمل قبل ما تدخل بيانات حقيقية.

## تنبيه طبي

التطبيق ده أداة **متابعة شخصية**، وليس تشخيصاً طبياً ولا بديلاً عن استشارة الطبيب. النطاقات المستهدفة الافتراضية عامة ولازم تتظبط مع الطبيب المعالج.
